# 플로팅 챗봇 오케스트레이션 재구성 및 명칭 정리

- **ID**: 005
- **날짜**: 2026-03-23
- **유형**: 기능 추가

## 작업 요약
플로팅 챗봇의 현재 질문-답변 플로우를 분석한 결과, 백엔드 에이전트는 이미 오케스트레이션 방식으로 동작하지만 프론트엔드가 자체 추정 trace를 먼저 그리는 구조였다.
이를 실제 백엔드 오케스트레이션 이벤트 기반으로 재구성해 실행 상태와 계획을 더 정확하게 표시하도록 바꾸고, 챗봇 이름을 `플라즈마 에이전트 챗봇`으로 정리했다. 기존 최종답변의 품질 보강과 마지막 응답 형태는 유지했다.

## 변경 파일 목록
- `src/model/struct/agent.py`
  - 오케스트레이션 스냅샷 SSE 이벤트 추가
  - 난이도 판정, trace 단계, 파이프라인 컴포넌트 구성을 백엔드에서 생성하도록 정리
- `src/app/component.chat.floating/view.ts`
  - 프론트의 가상 trace 초기화를 제거하고 백엔드 orchestration 이벤트를 기준으로 상태를 반영
  - `read_page_results` 도구 실행 로그와 단계 표시 보강
- `src/app/component.chat.floating/view.pug`
  - `TRACE MODE`, `TRACE READY` 등 용어를 제거하고 오케스트레이션 실행 상태 중심 UI로 정리
  - 챗봇 명칭을 `플라즈마 에이전트 챗봇`으로 변경
- `src/app/component.chat.floating/app.json`
  - 컴포넌트 title을 `플라즈마 에이전트 챗봇`으로 변경

## 변경 패턴
- Before
  - 백엔드 에이전트는 오케스트레이션 방식이지만, 플로팅 UI는 프론트에서 추정한 trace/분류를 먼저 렌더링했다.
  - `TRACE MODE` 명칭이 실제 기능 설명보다 마케팅성 라벨에 가까웠다.
- After
  - 플로팅 챗봇은 백엔드가 보낸 실제 오케스트레이션 스냅샷으로 단계/계획/UI를 구성한다.
  - 사용자에게는 `플라즈마 에이전트 챗봇`과 오케스트레이션 실행 상태라는 더 명확한 개념으로 노출된다.
