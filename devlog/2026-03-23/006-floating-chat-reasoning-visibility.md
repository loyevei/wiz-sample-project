# 플로팅 챗봇 실행 사고 로그 가시화 강화

- **ID**: 006
- **날짜**: 2026-03-23
- **유형**: 기능 추가

## 작업 요약
플로팅 챗봇이 에이전트로서 최종답변을 만들기 전에 거치는 실행 사고 과정을 더 자세히 보여주도록 UI와 백엔드 이벤트를 강화했다.
내부 비공개 추론을 그대로 노출하는 대신, 실제 실행 가능한 reasoning trace 형태로 질문 분류, 키워드 추출, 파라미터 매핑, 페이지 선정, 페이지 결과 추출, 근거 수집, 답변 통합, 페이지 handoff까지 전 과정을 표시하도록 정리했다.

## 변경 파일 목록
- `src/model/struct/agent.py`
  - trace 단계를 16단계로 세분화
  - 키워드 추출, 파라미터 매핑, 목표 페이지 선정, 페이지 결과 추출 단계를 명시적으로 포함
- `src/app/component.chat.floating/view.ts`
  - 메시지별 `reasoningLogs` 추가
  - orchestration / pipeline / tool / quality / navigation 이벤트를 시간순 실행 사고 로그로 축적
  - `read_page_results`와 `navigate_to_page`를 별도 사고 단계로 반영
- `src/app/component.chat.floating/view.pug`
  - `실행 사고 로그` 섹션 추가
  - 페이지 이동, 키워드 인자 반영, 결과 추출 과정이 사용자에게 직접 보이도록 UI 추가

## 변경 패턴
- Before
  - 단계 카드와 도구 로그는 있었지만, 키워드→페이지→결과 추출→최종답변으로 이어지는 전체 사고 흐름이 충분히 드러나지 않았다.
- After
  - 질문 분류부터 페이지 결과 추출, handoff까지 실제 에이전트 실행 흐름이 순차 로그와 세분화된 단계 카드로 모두 보인다.
  - 최종답변 방식과 페이지 이동 후 결과를 읽어 정리하는 기존 구조는 그대로 유지된다.
